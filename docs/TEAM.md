- 3D 스캐너 / PatchCore / YOLO 쪽을 아는 사람이 **B** 를 맡는 게 가장 빠릅니다 (실제 데이터가 MES 로 들어오는 입구).
- **A** 는 기능 양이 적은 대신 1주차 기반 작업과 코드 리뷰·통합을 맡습니다.
- **C·D** 는 1주차에 C 가 만드는 더미 데이터(F02)로 바로 화면 개발을 시작합니다. B 를 기다리지 않습니다.

## 규칙
- `models.py`, `schemas.py` 는 **A 가 관리**. 필드가 필요하면 A 에게 요청하거나 PR
- 여러 기능이 같이 쓰는 파일은 [FEATURES.md 5장](FEATURES.md#5-여러-기능이-같이-쓰는-파일-규칙) 규칙대로
- `main` 직접 push 금지 → `feature/F번호-이름` 브랜치 → PR(제목 `[F05] ...`) → 1명 이상 리뷰 후 merge
- PR 올리기 전 `cd backend && pytest -q` 전체 통과
- `.env` 는 올리지 않음. 각자 `.env.example` 복사해서 사용
- Python 3.11+, Node 20+, MySQL 8 로 통일

## 일정 요약 (5주 예시)
1. **1주차** — F00 뼈대, F01 데이터 계약 확정(전원 리뷰), F02 더미 데이터, B 는 `build_filename`·`judge_dimension` 먼저
2. **2~3주차** — 각자 1단계 기능 병렬 개발, 매주 금요일 30분 데모·점검
3. **4주차** — F16 실제 라인 연동(B 주도, 전원), F17 Docker, 버그 수정
4. **5주차** — F18 발표 준비·리허설

주차별 담당 표는 [FEATURES.md 3장](FEATURES.md#3-일정표).
